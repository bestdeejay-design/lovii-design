# SCHEME — как устроена и как подключается дизайн-система

Одностраничная карта фреймворка для владельца и агентов: кто где правит, как стиль
доезжает до сайтов, как подключить новый. Детали: [README.md](README.md) (что такое ДС),
[SKILL.md](SKILL.md) (режимы подключения и цикл для агентов), [CHANGELOG.md](CHANGELOG.md)
(версии), [tools/targets.json](tools/targets.json) (реестр потребителей).

---

## 2. Два артефакта

| Артефакт | Состав | Для кого |
|---|---|---|
| `lovii.css` | слой A (токены + база) + слой B (компоненты) | классические сайты: lovii.ru, lovii-site |
| `lovii-tokens.css` | слой A + compat-алиасы легаси-имён, БЕЗ компонентов | витрина с собственной анатомией: lovii-demo |

## 3. Режим снапшотов (прод)

На каждый сайт-потребитель кладётся **копия артефакта** (снапшот) с провенансом в
шапке: версия токенов, дата сборки, хеш коммита lovii-design. Сайт подключает
снапшот `<link>`-ом, поверх — свой слой, которому разрешено краситься **только**
через `var(--lv-*)`; голый hex запрещён и ловится стражами.

Почему снапшоты, а не прямая ссылка на Pages: сайт не зависит от чужого CDN,
каждый снапшот знает свою версию (проверяемо curl-ом, откатываемо коммитом),
обновление — атомарный коммит в репо сайта.

Для прототипов допустим режим live-CDN (прямая ссылка на Pages lovii-design) —
см. SKILL.md «три режима». Для прод-сайтов — только снапшоты.

## 4. Цикл правки стиля

1. `git -C lovii-design pull` — убедиться, что локальная копия не отстала
   (рассинхрон «локаль vN-1 / прод vN» = риск разнести старый стиль).
2. Правка токенов/компонентов **только здесь**, в lovii-design.
3. `python3 tools/propagate.py --push` — соберёт артефакты, разнесёт снапшоты во
   всех потребителей из targets.json, прогонит стражи, сделает точечные коммиты
   и пуши. Предохранители: STOP при незакоммиченном/непушенном lovii-design;
   коммитится ТОЛЬКО файл снапшота.
4. CDN Pages обновляется до 10 минут — live-приёмку гонять с учётом кэша.

Править `lovii.css` / `lovii-tokens.css` руками на сайтах-потребителях ЗАПРЕЩЕНО
(AGENTS.md пр.14) — только через этот цикл.

## 5. Стражи

| Страж | Что ловит |
|---|---|
| `tools/check-sync.py` | снапшоты ≠ канону lovii-design; hex в слоях сайтов |
| `scripts/check_lovii_site_paths.py` | битые/абсолютные ссылки, слэши (lovii-site) |
| `scripts/check_lovii_site_facts.py` | легаси-цифры, канон-формулировки, **md5-пины логотипов**, запрет #f3ebf0 в SVG |
| `scripts/smoke_lovii_site.py` | 7 страниц: консоль, темы, 390px, лид-форма |
| `scripts/check_demo_tokens.py` | легаси-имена (--pink и пр.) вне compat-слоя (демо) |
| live-скрипты `scripts/live_*.py` | приёмка на проде: меню, бургер, логотип, токены |

## 6. Онбординг нового сайта (5 шагов)

1. Выбрать артефакт: полный `lovii.css` (типовой сайт) или `lovii-tokens.css`
   (своя анатомия, как у витрины).
2. Вписать потребителя в [tools/targets.json](tools/targets.json): repo, dest,
   branch, guards, live, notes.
3. В `<head>` сайта — `<link>` на будущий снапшот.
4. Собственный CSS сайта перевести на `var(--lv-*)` (hex запрещён).
5. `python3 tools/propagate.py --push` — снапшот приедет сам, стражи проверят.
